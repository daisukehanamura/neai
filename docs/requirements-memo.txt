
もちろん。Claude Codeにそのまま渡せるように、**「何を作るか」「技術構成」「段階的な実装方針」「制約」**までまとめる。

なお、最新仕様を確認したところ、現在のOpenAI Realtime APIはブラウザ/モバイルからはWebRTC推奨で、音声会話だけでなく画像入力・Function Callingにも対応している。Cloudflare Durable ObjectsはWebSocketの長時間接続や状態管理に使える。Vercelも2026年6月からWebSocketをPublic Betaでサポートしているので、以前より選択肢が広がっている。

以下をClaude Codeへの最初の指示文として丸ごと貼ればいい。

iPhone XR 自作AI常設端末

1. プロジェクト概要

使っていない iPhone XR を、家庭に常設する「自分専用のAI音声アシスタント端末」にする。

イメージとしては Alexa+ / Gemini Live / ChatGPT Voice のような体験だが、既存サービスをそのまま使うのではなく、自分でWebアプリとバックエンドを実装して拡張可能なAI端末を作る。

iPhone XRを棚や机などに固定し、電源につないで常時待機させる。

ユーザーはiPhoneを手に取ったりアプリを操作したりせず、

「ねえAI、今日の天気は？」

「ねえAI、これ何？」

「ねえAI、これってどういう意味？」

などと話しかけるだけでAIと会話できるようにする。

「これ何？」など画像が必要な質問の場合は、iPhoneのカメラから現在の映像を取得し、画像をAIに渡して回答させる。

最終的には「自分専用Alexa」のようなAI家電を目指す。

2. ハードウェア

既存のiPhone XRを利用する。

追加ハードウェアは原則不要。

iPhone XRが持っている以下を利用する。

* マイク
* スピーカー
* カメラ
* Wi-Fi
* ディスプレイ
* バッテリー

ラズパイは使用しない。

当初はRaspberry Pi 5 + Camera Module + マイク + スピーカーという構成を検討したが、ハードウェア費用が高いため、余っているiPhone XRを端末として利用する方針に変更した。

3. 目指すユーザー体験

基本的な音声会話

iPhoneを常時待機させる。

ユーザー：

「ねえAI」

AI：

「はい」

ユーザー：

「今日の天気は？」

AI：

「今日は晴れで、最高気温は……」

という会話。

質問後、できるだけ早く回答音声が開始されることを重視する。

画像付き質問

ユーザー：

「ねえAI、これ何？」

このときWebアプリがiPhoneのカメラから現在の画像を取得する。

画像＋ユーザーの質問をAIに渡す。

AI：

「これはコーヒーカップです。」

と音声で回答する。

ユーザーがカメラアプリを開いたり、撮影ボタンを押したりする必要はない。

最初のブラウザ権限許可だけは必要。

その他の想定質問

* 「今日の天気は？」
* 「明日の天気は？」
* 「今何時？」
* 「これ何？」
* 「この文字どういう意味？」
* 「この画面のエラー何？」
* 「この料理どうやって作る？」
* 「これの賞味期限いつ？」
* 「さっき何を話した？」
* 「買い物リストに牛乳を追加して」

など。

将来的には外部APIや自分で作ったFunctionをAIから呼び出せるようにする。

4. 最重要要件

低レイテンシ

「質問を言い終わってから、AIが回答を喋り始めるまで」をできるだけ短くする。

目標：

* 通常の音声会話：1秒前後で回答開始を目指す
* 画像付き質問：1〜3秒程度で回答開始を目指す

回答全文を生成してから音声再生するのではなく、ストリーミングで生成された音声をすぐ再生する。

OpenAI Realtime APIを利用する。

OpenAIの現在のドキュメントでは、ブラウザ/モバイルからのRealtime接続にはWebRTCが推奨されているため、まずWebRTC構成を優先して検討する。

参考：
https://developers.openai.com/api/docs/guides/realtime-webrtc

5. AI

OpenAI Realtime APIを第一候補とする。

Realtime APIは、

* 音声入力
* 音声出力
* テキスト
* 画像入力
* Function Calling
* 会話状態

を扱えるため、このプロジェクトとの相性が良い。

通常の音声会話ではRealtime APIによるSpeech-to-Speechを利用する。

画像が必要な質問では、現在のカメラフレームを会話へ画像入力として追加する。

モデルは最新のRealtimeモデルを使用する。

ただし、Claude Codeが実装時点でOpenAI公式ドキュメントを確認し、現在利用可能なモデル/API仕様に合わせること。

古いRealtime API Betaの実装方法をそのまま使わない。

7. Cloudflareの役割

Cloudflareをバックエンドとして利用する。

主な役割：

* 認証
* OpenAI APIキーなど秘密情報の保持
* Realtimeセッション初期化
* API中継
* 外部API呼び出し
* Function実行
* 会話状態管理
* 必要なら会話履歴保存

Cloudflare Workersを基本とする。

リアルタイム接続や状態管理が必要になった場合はDurable Objectsを利用する。

Durable ObjectsはWebSocket接続や状態を扱えるため、将来的な複数端末・長時間セッションにも対応できる。

参考：
https://developers.cloudflare.com/durable-objects/

8. Vercelについて

Next.jsのフロントエンドをVercelにデプロイする構成も可能。

ただし、リアルタイム通信のバックエンドについてはCloudflareを第一候補とする。

構成候補：

構成A

Vercel
↓
Cloudflare Workers
↓
OpenAI

構成B

Cloudflare Pages / Workers
↓
OpenAI

最初の実装では、最も単純な構成を選択する。

Vercelを必ず使う必要はない。

Vercelは現在WebSocketをPublic Betaでサポートしているため、必要ならVercelだけで構成する選択肢もある。

ただし、このプロジェクトではCloudflareのWorkers/Durable Objectsをリアルタイムバックエンドとして使う方向を優先する。

9. セキュリティ

このアプリは個人専用。

インターネット上にデプロイするが、不特定多数が利用できる状態にはしない。

必ず認証を入れる。

理想：

Internet
↓
Cloudflare Access / 認証
↓

↓

自分のiPhoneだけが利用できるようにする。

OpenAI APIキーをクライアント側JavaScriptに絶対に埋め込まない。

10. 常時待機

iPhone XRは家庭に固定して電源につなぐ。

Webアプリを常時表示する。

画面には最低限、

「AI待機中」

などを表示する。

Wake Lock API等を利用して画面スリープを防ぐ。

ただし、iOS/Safariの制約上、完全なバックグラウンド常時マイク待機は難しい可能性がある。

そのため第一段階では、

「Webアプリを前面表示した状態で常時待機」

を実現する。

iOSの制約を回避するために無理なハックをしない。

11. ウェイクワード

理想：

「ねえAI」

と話しかける。

ウェイクワードを検出したらRealtime AIとの会話を開始する。

重要：

「ねえAI」を検出するだけの待機状態では、可能な限りOpenAI APIへ音声を送り続けない。

理由：

* コスト削減
* プライバシー
* ネットワーク負荷削減

まずは実装を簡単にするため、

「待機ボタンを押して会話開始」

でもよい。

その後、

「ねえAI」

のウェイクワード検出を追加する。

ウェイクワード検出方式についてはClaude Code側で実装候補を調査する。

ブラウザだけで難しい場合は、まずPush-to-Talk版を完成させる。

12. カメラ

iPhoneのWebブラウザからカメラを取得する。

MediaDevices.getUserMedia()等を利用する。

ユーザーはカメラアプリを操作しない。

初回アクセス時のみカメラ権限を許可する。

基本動作：

ユーザー：

「ねえAI、これ何？」

↓

音声認識

↓

質問内容から画像が必要と判断

↓

カメラから現在フレームを取得

↓

AIへ画像を送信

↓

AIが画像を理解

↓

音声で回答

13. カメラの使い方

常時画像をAIに送信する必要はない。

基本は、

「質問に画像が必要なときだけ撮影」

とする。

例えば：

「今日の天気は？」

→ カメラ不要

「これ何？」

→ カメラ必要

「この画面のエラー何？」

→ カメラ必要

「この料理どうやって作る？」

→ カメラ必要

16. 会話履歴

会話の文脈を維持する。

例：

ユーザー：

「明日の天気は？」

AI：

「雨の予報です。」

ユーザー：

「じゃあ傘いる？」

AI：

「持っていった方がよさそうです。」

というように、直前の会話を理解する。

最初はRealtime Session内の会話履歴だけでよい。

長期記憶は後から実装する。

20. 非機能要件

最重要：

低レイテンシ

質問終了
↓
できるだけ早くAIの音声開始

目標：

通常会話 1秒前後

画像質問 1〜3秒程度

回答全文を待たない。

ストリーミングで回答する。

安定性

Realtime接続が切れた場合、自動再接続する。

iPhoneのSafari/WebKitの制約を考慮する。

コスト

常時AI接続しない。

ウェイクワード待機中はOpenAIへの音声送信を避ける。

画像も必要な場合だけ送る。
