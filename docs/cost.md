# 費用

## 課金の仕組み

Realtime API の課金は**接続時間ではなくトークン単位**。
ただし接続中はマイク音声を送り続けるため、**実質的には繋いでいる時間がそのまま費用になる。**

100万トークンあたりのドル価格（2026-08-29 時点 /
[公式](https://developers.openai.com/api/docs/pricing)）:

| | gpt-realtime-2.1 | gpt-realtime-2.1-mini |
|---|---|---|
| 音声入力 | $32.00 | $10.00 |
| 音声入力（キャッシュ） | $0.40 | $0.30 |
| 音声出力 | $64.00 | $20.00 |
| テキスト入力 | $4.00 | $0.60 |
| テキスト出力 | $24.00 | $2.40 |
| 画像入力 | $5.00 | $0.80 |

音声はおよそ入力600トークン/分・出力1200トークン/分。

## 目安（1ドル150円換算）

| 使い方 | gpt-realtime-2.1 | mini |
|---|---|---|
| 1往復の短い会話（10秒聞いて5秒話す） | 約1.5円 | 約0.5円 |
| 画像1枚 | 約1円 | 約0.2円 |
| **接続しっぱなし1時間** | **約170円** | 約54円 |
| **24時間つなぎっぱなし1ヶ月** | **約12万円** | 約3.9万円 |

**危険なのは会話そのものより切り忘れ。**
1往復1.5円なら1日20回話しかけても30円だが、一晩放置すると1400円になる。

## 費用が暴走しないための仕組み

| 仕組み | 効果 |
|---|---|
| **無操作60秒で自動切断** | 切り忘れを塞ぐ。設定画面で変更できる |
| **ウェイクワードは端末内で検出** | 待機中は音声を送らない。待機の費用はゼロ |
| **タイマーの計測は端末内** | 設定後は接続を維持しなくてよい（後述） |
| **カメラは呼ばれたときだけ撮る** | 映像を WebRTC に載せていないので常時の帯域も課金もない |
| **画面に実費用を表示** | 推定ではなく `response.done` の実測トークン数から計算 |
| **モデルを mini に切り替え可能** | 約3分の1 |

**最後の砦は OpenAI 側の Usage limits。** 実装側の対策はバグや想定外の挙動で
破られうるので、必ず月額上限を設定しておくこと。

## 実測の仕組み

`src/pricing.ts` が `response.done` の `usage` を集計している。**推定値ではない。**

```
input_token_details  … audio_tokens / text_tokens / image_tokens / cached_tokens_details
output_token_details … audio_tokens / text_tokens
```

キャッシュ分は入力トークン数に含まれるため、二重に数えないよう差し引いている。
画面下部にトークン内訳も出しているので、**何が費用を食っているかが見える。**

モデルを増やしたときは `src/pricing.ts` の料金表も更新すること。

## 未確定

**AI の発話テキスト（`response.output_audio_transcript`）が
テキスト出力トークンとして課金されるかは公式ドキュメントに明記がない。**

推測で答えないために、画面のトークン内訳で実測できるようにしてある。
「テキスト 出」が増えるかどうかで判断できる。
仮に課金されても、2文の回答で50トークン程度なら0.2円未満で誤差の範囲。

## 機能の呼び出しは課金される

**「端末内で動く機能」でも、呼び出す会話そのものは OpenAI を通る。**

「三分測って」の内訳:

| 段階 | 課金 |
|---|---|
| あなたの発話（音声入力） | あり |
| `set_timer` を呼ぶ判断（テキスト出力） | あり |
| 実行結果を返す（テキスト入力） | あり |
| 「三分ですね」（音声出力） | あり |
| **以降のカウントとアラーム（端末内）** | **なし** |

合計は普通の1往復と同じで**約1〜2円**。

### それでも端末内で持つ理由

代案と比べると差が出る。LLM に「3分待って教えて」をやらせるなら、
その間ずっと接続を維持する必要がある。

| 方式 | 3分タイマー | 30分タイマー |
|---|---|---|
| **端末内（現在）** | **約1〜2円** | **約1〜2円** |
| 接続を維持して LLM に待たせる | 約10円 | 約85円 |

タイマーの長さによらず費用が一定なのが端末内方式の利点。

### ローカルコマンドなら呼び出しも無料（実装済み）

Vosk はウェイクワードのために常時動いている全文認識器なので、
その結果をそのままコマンド照合に使える。**追加コストはゼロ。**

決まった言い回しは **OpenAI に一切繋がずに処理する。** 返事も端末内の音声合成で返す。

| 言い方 | 費用 |
|---|---|
| 「タイマー三分」 | **ゼロ** |
| 「タイマー止めて」 | **ゼロ** |
| 「今何時」 | **ゼロ** |
| 「あと何分」 | **ゼロ** |
| 「ねえクラピカ、三分測って」 | 約1〜2円（AI 経由） |

照合できなかった発話は従来どおり AI に渡る。曖昧な言い方や込み入った依頼は
AI が引き受け、決まりきったものだけを端末が引き取る形。

設定画面で切れる。認識対象が増えるぶん、ウェイクワードの精度に
影響する可能性があるため。

## 会話が長くなると高くなる

**会話全体が毎回モデルへ送られる**ため、ターンが進むほど入力トークンが増える。
キャッシュが効くので単価は下がる（音声キャッシュは $0.40/1M）が、
長時間の連続会話は避けたほうがよい。無操作切断はここにも効いている。
