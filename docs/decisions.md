# 決定の記録

何をなぜ選んだか。**捨てた案と、立てて反証した仮説も残してある。**
同じ検討を繰り返さないため、そして「なぜこうなっているのか」を後から辿れるようにするため。

## 採用したもの

### バックエンドは薄く。WebRTC はブラウザと OpenAI を直結する

出発点のメモは `iPhone → Cloudflare → OpenAI → WebRTC → iPhone` という中継構成だったが、
これは**誤り**だった。WebRTC では音声はブラウザと OpenAI を直接流れ、
サーバはセッション初期化だけを担う。

この誤りが直った結果:

- 中継ホップが無いので、レイテンシ目標1秒が現実的になった
- **Durable Objects が MVP で不要**になった。リアルタイム接続は DO を通らない
- Worker の役割は「トークン発行所 + ツール実行所」に縮小した

厚いバックエンド（DO で WebSocket 中継）も検討したが、遅延が乗るうえ、
音声のエンコードとジッタとエコーキャンセルを自前で持つことになるため見送った。

### セッション確立は Unified Interface

ephemeral token 方式だと短命キーとセッション設定がクライアントに渡る。
Unified Interface なら **APIキーも instructions もツール定義も一切渡らない。**
確立時の一往復だけなので通話中の遅延には影響しない。

### フロントは Vite + React SPA を Workers に同梱

単一画面のキオスクに SSR の利点がない。Vercel + Cloudflare の2デプロイ構成も
検討したが、ドメインが2つになり CORS と認証が二重管理になるため見送った。
`wrangler deploy` 1コマンド、1ドメインで完結する。

### カメラは「モデルに呼ばせる」

出発点のメモは「質問内容から画像が必要と判断」＝クライアント側の文言判定だった。
これは誤爆と取りこぼしが出る。**ツールとして定義してモデルに判断させる**方式にした結果、
判定ロジックがゼロになり、想定外の言い回しにも追従する。

ただし**既定で呼ばれすぎる問題**が実際に起きた。原因は instructions が
「推測せずに呼んでください」と呼ぶ方向に寄せていたこと。
既定を「呼ばない」に反転し、呼ぶ例と呼んではいけない例を明示して直した。
併せてツールに `target` 引数を必須化し、「何を見るのか」を書かせて安易な呼び出しを抑えている。

### カメラの既定は内側

棚に立てて画面をこちらへ向けて使うため、物を見せる向きも画面側になる。
UI から切り替えられるが、**会話中は切り替えられない**（カメラを同時に2本掴めないため）。

### 認証はデバイストークン方式

Cloudflare Access も検討したが、セッション期限による再ログインが
**無人常設端末と相性が悪い。** 長いランダムキーを一度だけ入れて localStorage に保存し、
Worker が定数時間比較で検証する方式にした。

### ウェイクワードは Vosk

[後述の「Picovoice」](#picovoice-porcupine-無料枠が廃止された)を参照。
Apache-2.0、アカウント不要、日本語モデルあり、iOS Safari で動作確認済み。
**全文認識なので、将来のローカルコマンド層（タイマー等）にも使い回せる。**

### ウェイクワードの語は「ねえクラピカ」

認識しやすさは「長い・子音が立っている・日常会話に出てこない」で決まる。

| 候補 | 評価 |
|---|---|
| **ねえクラピカ** | 破裂音が3つ（ク・ピ・カ）。日常語と衝突しない |
| ハンターハンター | 8モーラと長く、判断材料が多い |
| 幻影旅団 / キメラアント | 長く、まず言わない語 |
| ねえAI | **母音中心で弱い。** テレビ等で「AI」を拾って誤検出しやすい |

候補はすべてモデルの語彙表（20.7万語）に存在することを確認済み。
「AI」「エイアイ」は語彙に無いため「エーアイ」を使う必要がある。

これは音韻構造からの理屈であり、**実機での比較はまだ**。設定画面で切り替えて試せる。

### タイマーは端末内で完結させる

「3分測って」のたびに WebRTC を張って課金するのは無駄で、しかも1秒待たされる。
設定した後は **LLM もネットワークも通らない。**
終了時刻を**絶対時刻**で保存するのが肝で、相対秒数だと再読み込みで狂う。

長時間のアラーム（翌朝など）は Durable Objects の Alarms が本来の解だが、
そこから iPhone へ伝える手段（常時 WebSocket か Web Push）が要る。
**iOS の Web Push はホーム画面に追加した PWA でしか動かない。** MVP では扱わない。

### 天気は Worker 経由

Open-Meteo は APIキー不要だが、外部APIの差し替えや将来のキー管理を
クライアントから切り離しておくため Worker に置いた。

### 設定は localStorage に持つ

常設端末なので、設定のたびに `.env` を編集して再起動では使い物にならない。
環境変数は**初期値としてのみ**使う。

## 捨てたもの・反証されたもの

### Picovoice Porcupine — 無料枠が廃止された

当初の第一候補だったが、**無料枠が2026年6月30日で廃止**された。
既存の無料 AccessKey も無効化され、有料プランは月額 $899 から。
サインアップも法人メール必須に変わっている。個人プロジェクトでは採用できない。

なお、仮に使えたとしても**付属の `WebVoiceProcessor` は使えなかった。**
これは自分で `getUserMedia` を呼ぶが、iOS ではマイクを取り直せないため。

### 「映像トラックが無いと音が受話口へ出る」— 反証

観測された現象から立てた仮説だったが、総当たり実測の結果**再現しなかった。**
音声のみの取得でもスピーカーから鳴る。詳細は [ios-constraints.md](ios-constraints.md)。

### クライアント側での「画像が必要か」判定 — 不採用

前述のとおりモデルに判断させる方式にした。

### Durable Objects をリアルタイム接続に使う — 不要

リアルタイム接続は DO を通らない。DO が要るのはクォータ計数・長期記憶・
複数端末の共有状態で、いずれも先の話。

### 自前のダウンサンプラ — 不要になった

Porcupine 用に AudioWorklet で 16kHz / 16bit のフレームを作っていたが、
Vosk は `AudioContext({ sampleRate: 16000 })` を直接要求できるため不要になり、削除した。

### 表示ツールを呼ばせて構造化画面を作る案 — 保留

function call は音声生成を中断するため、「喋りながら画面も描く」を1レスポンスで
行うのが難しく、**要件の最重要項目である「1秒で喋り始める」を犠牲にする。**

代わりに、まず発話テキストをそのまま表示する方式を入れた（レイテンシ影響ゼロ）。
構造化が要るなら、音声レスポンスの**後に** `output_modalities: ["text"]` の
応答を追加する案が有力。音声には影響しない。

## 出発点のメモから変更した前提

`requirements-memo.txt` は叩き台なので、以下は現状と食い違う。

1. **中継構成** → 誤り。WebRTC はブラウザと OpenAI を直結する
2. **Durable Objects をリアルタイム接続に** → MVP では不要
3. **クライアント側で画像の要否を判定** → モデルに判断させる
4. **Next.js / Vercel** → Vite SPA + Workers の単一デプロイ
5. **Cloudflare Access** → デバイストークン方式
6. **ウェイクワードは Picovoice** → 無料枠廃止により Vosk
7. **ウェイクワードは「ねえAI」** → 認識しやすさから「ねえクラピカ」
